# Virtual Avatar Studio 開發規則

## 基本原則

- 先分角色，再分素材類型。
- 頂層資料夾只放跨角色共用資料。
- 角色專屬檔案不要放在專案根目錄。
- 重要產物保留來源檔、可用版本、輸出版本三層，不只留最終圖片。

## 現有角色與工作入口

- `v-skin` 是本專案別名。專案總覽對話對應根目錄，角色對話對應 `01_角色/<角色名>/`。
- 凜（Rin）：`01_角色/Rin/README.md`。
- 包子（Baozi）：`01_角色/Baozi/README.md`。
- 包子的現行整包位於 `01_角色/Baozi/03_Live2D/既有專案整包/`，其中的 `tools/`、`source/`、`work/`、`export_vts/` 保持相對位置；執行既有素材工具時以該整包為專案根。
- 先確認角色與版本，再修改工程。角色自己的舊工作歷史與修復草稿只作回溯來源，不自動升格為正式版本。

## 新增角色

新增角色時，在 `01_角色` 下建立：

```text
<角色名>/
  README.md
  00_角色設定/
  01_原始素材/
  02_可用版本/
  03_Live2D/
  04_輸出與發布/
  99_封存/
```

`README.md` 至少記錄：

- 角色定位
- 目前最新版本
- 主要素材來源
- 重要輸出位置
- 待辦或下一步

## 命名建議

- 角色資料夾使用穩定名稱，例如 `Rin`、`Mio`、`Baozi`。
- 版本檔加上 `v1`、`v2` 或日期，避免覆蓋不明。
- 測試、廢案、舊版放入該角色的 `99_封存`，不要散在頂層。

## 與 AI 形象素材區的關係

`@/workspace/00_Admin/AI形象素材` 是角色形象素材庫；本專案是虛擬形象開發工作區。

- 已定稿的頭像、banner、桌寵素材可同步參考 AI 形象素材區。
- Live2D 拆圖、綁定工程、互動預覽、開發紀錄優先留在本專案。
- 若兩邊都有版本，以角色 README 記錄哪個是目前基準。

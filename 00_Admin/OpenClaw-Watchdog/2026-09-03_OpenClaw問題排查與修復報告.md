# OpenClaw 問題排查與修復報告

## 1. 報告資訊

- **日期：** 2026-09-03
- **設備：** DESKTOP-AAT5AIR
- **作業系統：** Windows
- **OpenClaw 安裝位置：** 本機 npm 全域安裝
- **報告範圍：** OpenClaw Gateway、agent 工作區、Discord、Node、Watchdog、設定遷移與版本狀態
- **敏感資料處理：** 本報告不記錄任何 token、OAuth 憑證或其他密鑰內容

## 2. 使用者觀察到的問題

升版與修復過程後，OpenClaw 的助理設定看起來像被重置：

- 主助理的名稱、語氣與長期記憶沒有被正確載入。
- OpenClaw 似乎使用了新的預設工作區，而不是原本澪的工作區。
- Gateway、Discord 與部分 agent 設定同時出現異常，容易讓問題看起來像整個助理設定遺失。

## 3. 初始排查結果

### 3.1 Gateway 與服務

- Gateway Windows Scheduled Task 原本處於 Disabled／Stopped 狀態。
- 另有手動或 Watchdog 啟動的 Gateway 程序佔用 `127.0.0.1:18789`，造成服務管理與實際程序不一致。
- Watchdog 曾在 Gateway 服務狀態不一致時啟動額外程序，存在重複啟動風險。

### 3.2 設定檔與版本相容性

- 原設定檔含有舊版本已不接受的設定鍵，例如舊版 memory、Control UI、Tailscale、Node command deny-list 與 metadata 欄位。
- `agents.defaults.systemAgent.agentId` 缺失，導致部分主動任務無法判斷要使用哪個 agent。
- Discord plugin 版本落後於 OpenClaw 主程式，曾出現缺少 `privateFileStore` 的匯入錯誤。

### 3.3 安全性

- Gateway token 與 Discord token 原先以明文存在設定或服務啟動檔中。
- Discord 群組政策原先為 `open`，但沒有相應的伺服器／群組 allowlist。
- 發現一筆待處理的裝置配對請求。

### 3.4 狀態遷移

- SQLite 狀態需要執行 `audit-events-v2` 遷移。
- 舊版 Memory Core 主機事件仍有 legacy source，需要匯入新版 plugin state。
- 舊版 workspace setup state 需要轉移到共享 SQLite 狀態。

## 4. 助理設定被重置的實際原因

排查 agent 實際工作區後確認，設定內容並沒有整批遺失，而是主助理的工作區解析路徑改變：

```text
原本澪的工作區：
C:\Users\User\.openclaw\workspace

升版後新建的預設工作區：
C:\Users\User\.openclaw\workspace\main
```

`workspace\main` 內的 `AGENTS.md`、`SOUL.md`、`IDENTITY.md` 與 `USER.md` 都是在 2026-09-03 08:44 左右建立的預設模板；其中 `IDENTITY.md` 沒有填入名稱，`USER.md` 也只有預設範例內容。

原本澪的自訂設定仍保存在：

- `C:\Users\User\.openclaw\workspace\AGENTS.md`
- `C:\Users\User\.openclaw\workspace\SOUL.md`
- `C:\Users\User\.openclaw\workspace\IDENTITY.md`
- `C:\Users\User\.openclaw\workspace\USER.md`
- `C:\Users\User\.openclaw\workspace\MEMORY.md`

因此本次的核心問題是「main agent 讀錯工作區」，不是設定檔與人格資料被刪除。

## 5. 已完成的處理

### 5.1 設定備份與版本更新

- 保留並檢查 `openclaw.json`、`last-good`、`pre-update`、`.bak` 與具名歷史備份。
- 建立本次修復前備份，並將備份放入：

  ```text
  C:\Users\User\.openclaw\99_封存\2026-09-03_legacy-auth-backups\
  ```

- OpenClaw 主程式已更新並確認為 `2026.8.2`。
- Discord plugin 已同步至 `2026.8.2`。
- npm registry 顯示目前穩定版仍為 `2026.8.2`，目前沒有可用更新。

### 5.2 設定相容性修復

- 移除由新版 doctor 判定為無效或退休的設定鍵。
- 將 `main` 設為主系統 agent，避免背景任務出現 agent selection error。
- 補上各 agent 的模型與 fallback 設定：

  - `main`：`openai/gpt-5.6-sol`，fallback 為 `openai/gpt-5.6-terra`
  - `seki`：`openai/gpt-5.6-terra`，fallback 為 `openai/gpt-5.6-sol`
  - `gemma`：`ollama/gemma4:e2b`

- 將 Discord 群組政策改為 `allowlist`，避免未授權群組訊息直接觸發助理。
- 關閉 browser relay 的 legacy auth 行為。

### 5.3 密鑰與服務修復

- 將 Gateway 與 Discord token 從明文設定／服務檔移入 OpenClaw secret store。
- 服務啟動檔已不再包含 Discord token。
- 重建並啟用 OpenClaw Gateway Scheduled Task。
- 更新並重啟 OpenClaw Node。
- 核准新的待處理裝置配對請求。
- 重新啟用 OpenClaw Watchdog，並確認不會與正式 Gateway 產生重複程序。

### 5.4 狀態與工作區遷移

執行：

```powershell
openclaw doctor --fix --non-interactive
```

完成以下遷移：

- Memory Core host events 匯入 SQLite plugin state，共 31 筆新資料。
- 舊事件檔保留為 `.migrated` 封存檔。
- workspace setup state 與 attestations 匯入共享 SQLite state。
- 舊版 workspace state 在確認匯入成功後移除其退休來源。
- `TOOLS.md` 合併至 `AGENTS.md`，原檔保留為封存資料。
- `HEARTBEAT.md` 內容遷移至 main heartbeat 的 cron scratch。

### 5.5 接回澪的原本助理設定

將 `agents.entries.main.workspace` 明確設定為：

```text
C:\Users\User\.openclaw\workspace
```

之後重啟 Gateway，讓新版 OpenClaw 重新載入原本的澪設定與記憶檔案。新建的 `workspace\main` 沒有刪除，保留作為可回復參考。

## 8. 建議後續維護

### 每次升版前

```powershell
openclaw status
openclaw update status
openclaw update --dry-run
```

確認使用獨立 PowerShell 視窗執行升版，不要從 Gateway 自己的程序樹內啟動更新。

### 每次升版後

```powershell
openclaw doctor --lint --non-interactive
openclaw gateway status --deep
openclaw gateway health --json
openclaw agents list --json
openclaw secrets audit --json
openclaw update status --json
```

特別確認 `main` 的實際 workspace 是否仍為：

```text
C:\Users\User\.openclaw\workspace
```

### 備份原則

- 不要直接用舊版完整 `openclaw.json` 覆蓋目前設定。
- 舊版設定可能包含已失效的 schema、明文 token 或過時的模型配置。
- 優先採用「目前設定 + 選擇性恢復工作區／agent 欄位」的方式。
- 定期建立 OpenClaw 的版本化 backup repository，並將 `~\.openclaw` 中的 credentials、sessions 與其他敏感資料排除在公開版本控制之外。

## 9. 結論

本次問題已修復。主要原因是升版後新版 OpenClaw 為 `main` 使用了新建的預設工作區，造成澪的自訂人格與記憶看起來像被重置；原始資料實際上仍在本機工作區中。

目前已完成：

- 澪設定接回
- Gateway 與 Discord 恢復
- 舊版狀態遷移
- plugin 同步
- 明文密鑰清除
- Windows 服務與 Watchdog 修復
- OpenClaw 確認維持最新版 `2026.8.2`
